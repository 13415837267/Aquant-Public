# 数据目录说明

## 当前候选与计划文件

- `candidates.json` 是网页读取的当前候选快照。每次候选运行都会重新读取 `Aquant-Private/main` 最新策略；本轮版本号和提交 SHA 与实际执行源码匹配、通过未来函数及风险约束校验后，即可作为**研究/模拟候选**展示，无需等待研究完成或正式发布。提交 SHA 只用于追溯本次快照，不固定历史策略。
- `next_trading_day_plan.json` 必须与当前候选快照逐项对应；任何版本、数据截止日或候选不一致都会阻止展示。
- 候选生产按北京时间每日检查。优先使用最新已落库的完整交易日行情：交易日数据已更新则使用当日收盘数据；非交易日或当日行情尚未完整落库时，使用最近一个已落库交易日的数据，并明确显示数据时点。网页部署也以该最新有效历史日期为基准，不强制要求候选日期等于自然日当天。
- 研究中也会生成候选与模拟计划，但界面必须标注研究/模拟状态。正式发布门禁未通过时，`production_release` 始终为 `false`，禁止实盘和自动下单。
- 旧近期训练窗口模型的候选和计划已移入 `data/research/historical_candidates/`，仅用于历史审计，不属于 2.6.0 当前结果。新候选必须由当前策略真实重算生成，不得将历史输出改名冒充当前结果。
- 每次生成时动态检出个人策略仓库 main 分支最新提交；系统版本清单和研究状态按本轮实际策略自动同步。候选生产每日北京时间18:05与数据维护完成后检查；最新策略提交或已落库数据日期变化时重新生成，二者均未变化时可跳过重复计算。
- 数据维护按北京时间18:00、18:15、18:30、19:05、19:20和20:00设置定时检查；当日定时任务漏跑时，可通过主分支上的数据维护工作流变更触发云端补偿运行。数据维护完成后，候选生产工作流自动接续；必须以实际运行记录和新生成文件确认结果，不得把旧快照当成当日结果。

## 行情历史

历史日线数据按交易日保存为 gzip 压缩 CSV：

`data/history/YYYY/YYYY-MM-DD.csv.gz`

历史行情是共享数据资产，不随策略版本清理。数据维护使用增量更新，优先复用仓库已有数据。

## 采集与研究

历史文件可保留沪深京股票记录，不应以当前活动选股范围过滤重建历史行情；当前候选准入仍按私有策略配置限制为沪深主板 A 股。

数据维护、候选生成、研究校验与网页部署均由 GitHub Actions 云端执行。数据源凭据必须存放在 GitHub Actions Secrets 中，不能提交到源码仓库。

- 网页自动部署因 `github-pages` 环境审批保护曾出现等待并阻塞后续发布。现使用独立的 `aquant-pages-auto` 自动发布环境，部署请求显式匹配 OIDC 环境声明；部署前的候选日期、策略来源、版本一致性、未来函数与自动下单关闭校验仍然执行。以 GitHub Pages 部署接口确认成功为准，不以工作流已触发代替发布成功。

网页部署还有一项时序保护：模拟计划的下一交易日必须严格晚于北京时间当前日期。若执行日已经到达或过去，则当前计划视为已过期，不会作为未来可执行计划部署；待最新已完成交易日更新后重建。
