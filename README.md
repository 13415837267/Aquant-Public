# Aquant-Public

个人量化交易系统的**研究阶段运行仓库**：负责增量数据维护、研究候选生成、下一交易日模拟计划、历史归档、云端验证与网页展示。

## 当前系统版本与策略版本绑定

当前系统版本：**2.6.0**。唯一策略源 `Aquant-Private/main` 的策略版本也必须为 **2.6.0**，且必须匹配提交 `886a01a3a314dd1ba133b9273054b280e3bc871c`。系统版本清单位于 `config/system_version.json`，版本号、策略提交号或生命周期状态任何一项不一致，候选生成就会失败关闭。

当前生命周期为 **研究中**，不存在已发布的正式版本号。旧的“1.0.0”标识及近期训练窗口神经网络已归档，不再称为正式版本，也不再作为当前候选生成器。旧权重文件 `data/models/production_v1.json` 仅作历史比较，当前研究候选直接从 `Aquant-Private/strategy/model.py` 加载评分与准入函数。

### 当前研究策略契约

- 策略唯一来源：`Aquant-Private/main`，版本必须与系统版本一一对应。
- 当前策略版本：`2.6.0`；生命周期：仅研究。
- 市场上涨广度必须达到 **65%**，市场中位收益不得低于 **-0.30%**；市场条件不达标时允许零候选。
- 采用短期动量、隔夜结构、量能活跃度、价格强度、流动性与风险因子；硬性可交易性筛选先于横截面评分。
- 候选准入最多 2 只：0.89 主门槛、0.88 单只覆盖回退、0.85 每日 Top-1 回退；各层均受硬风险和市场门槛约束。
- 交易时序保持 `T 收盘 → T+1 开盘入场 → T+2 起最早退出 → 最长 5 个完整交易日`；当前研究的止盈目标为净收益 +1%，止损 -3%，仅作为待比较的基准参数。
- 不自动下单，不连接券商执行。版本对齐不代表策略已通过盈利门槛；未通过云端回测、成本压力、参数稳健性与未来影子验证，不得晋级。

## 研究与发布纪律

所有运行、训练、测试及验证必须在 GitHub Actions 云端完成；两个仓库均只保留 `main` 分支。Public 负责数据、研究候选生成、云端工作流与网页；Private 保存唯一策略实现和策略配置。

系统版本和策略版本必须严格相同；候选快照的 `strategy_version`、`strategy_commit` 必须同时匹配系统清单与当前 Private/main。旧候选如果与当前版本不一致，网页必须隐藏，而不是仅修改元数据把旧候选冒充为新策略结果。

正式发布门禁同时衡量验证期与补充评估期的组合净收益、平均单笔净收益、盈利因子、最大回撤、交易样本数、成本压力及相邻参数稳健性。发布前还必须经过至少 60 个未来交易日、至少 40 笔完整交易的影子模拟；历史补充期曾参与研究，不再视为完全独立留出。即便未来研究版本通过历史门禁，正式发布也与自动下单分开管理。

## Action 历史记录清理

GitHub Actions 历史记录由 `.github/workflows/cleanup-action-deployment-history.yml` 和 `scripts/cleanup_action_deployment_history.sh` 在云端维护。工作流在相关流程完成时自动运行，清理脚本更新时也会自动启动专项清理。

清理范围是**已完成且结论为“失败”“跳过”或“取消”**的历史 Action 运行。将已取消运行纳入清理，是为清除连续提交或实验替换所遗留的无效尝试；审计清单会保留每条被删除记录的运行编号、时间、名称和原结论。运行中、排队中的任务与成功运行必须保留；其他结论不在本轮清理范围。

清理只针对 GitHub Actions 运行记录，不删除 Deployment 记录、源代码、Git 提交、行情数据、模型、候选快照或其他项目资产。每次维护都会记录删除结果、保留的活动运行、成功运行、其他结论及错误，并以唯一运行编号保存审计清单至 `data/maintenance/action_deployment_cleanup/run-<运行编号>.json`。如平台接口导致目标记录删除失败，工作流会记录错误并以失败状态结束。

## 工作流架构

当前工作流围绕唯一策略版本运行，候选池始终作为研究/模拟快照；旧版生产资产只留作审计对照。

- `01 Python质量检查`：代码质量、语法和测试。
 该检查只在 Python 代码、测试、依赖或工作流文件变更时触发；纯历史数据检查点不会触发新的代码质量任务，避免长流程的数据提交互相取消。
- `02 数据维护`：北京时间18:00触发A股交易日检查与增量历史数据维护，并在18:15、18:30设置两次兜底触发，降低单次GitHub调度延迟或漏触发导致整日未更新的风险。重复运行采用增量更新，不重建已有历史。
- `03 候选池生产`：在 `02 数据维护` 成功后自动运行；系统版本清单、当前策略候选生成或下一交易日计划相关代码变更时，也会在 `main` 云端触发恢复验证。所有自动和代码变更入口统一检查当日交易日状态与最新历史行情日期；历史行情未覆盖今日时禁止生产旧快照，若候选快照已覆盖今日则跳过重复生产。仅明确填写信号日期的手动请求可按指定日期执行。
- `04 历史研究流水线`：正式研究、三段式时间切分、研究门禁和检查点。
- `05 网页自动部署`：候选生产工作流完成后进行快照门禁，仅当交易日状态、候选快照和下一交易日计划均对应今日且候选状态为 `ready` 时才部署。网页代码变更仍可直接触发构建；行情/状态文件提交不再抢先部署尚未生成新候选的旧快照。
- `06 模型研究`：独立实验入口，当前运行高精度严格标签与路径感知 GBDT。
- `07 历史候选回放`：手动指定历史信号日，复现旧模型对照资产候选。
- `08 成对排序定向复核`：复用06工作流缓存中的高精度研究产物，只复跑每日Top2固定规则对照并上传日志，不重新训练、不改动正式模型。
- `09 路径感知模型验证集阈值复利筛选`：训练一次后在验证集比较固定阈值网格，要求最低交易数、正复利和最大回撤均达标才可入选；按完整信号窗口计算收益，最终留出只评估验证集选出的阈值，不改变正式模型。

此前会因 `data/**` 更新而重复启动的两个独立训练工作流已移除；对应研究 Python 脚本继续保留，但不再自动触发。

## 自动更新

北京时间每天 **18:00** 自动触发市场数据更新检查，并在 **18:15、18:30** 设置两次兜底触发。所有触发均使用同一份增量维护流程；已完成今日数据和候选发布时，候选日期门禁会跳过重复生产。交易日检查脚本的 Python heredoc 必须完整闭合，工作流日志出现 shell/Python 语法警告时必须先修复，不得把警告视为可接受结果。

自动任务先读取中国 A 股交易日历并校验最新交易日状态；实际日线接口若返回有效当日行情，即使交易日历暂时漏列当天，也会以该有效行情补入增量更新。候选生产在自动触发、代码变更和无日期手动运行入口都执行当日状态与最新历史行情日期门禁；非交易日、状态过期或历史行情未覆盖今日时，不生成旧日期候选。网页部署另行校验交易日状态、候选快照日期和下一交易日计划信号日期，确保三者都是今日且候选状态为 `ready` 后才发布。

若今日数据尚未落库，可手动运行 `02 数据维护` 并启用“非交易日补齐最近一个已完成交易日的数据”输入项；当主分支修改并提交数据维护工作流本身时，也会自动触发一次增量恢复检查，便于云端修复后的立即验证。恢复模式只补齐缺失的最近完成交易日，不重新下载已有历史、不改变正式模型和候选规则。
- 数据维护采用“最新完整日期 + 1 → 最近完成交易日”的增量区间，只处理缺失交易日，不重新下载或重建已有历史数据。
- 增量起点仅依据历史文件存在性和基本日线字段确定；估值字段完整性由独立质量检查负责，避免字段版本差异导致重复重建旧日期。
- 历史文件为 `.csv.gz` 压缩格式，增量判断按完整文件名去除 `.csv.gz` 后解析日期，避免误把现有历史识别为不存在而回退到历史起点。
- 日线质量检查只验证仓库中最近已经落库且结构完整的交易日；北京时间18:00前不把当天尚未收盘的行情当作质量检查对象，避免开盘前误检当天数据。


- 实际交易日：只增量更新最新行情与历史数据，完成数据校验后按系统2.6.0绑定的 Private/main 策略进行评分和准入，再生成研究候选池与下一交易日模拟计划；旧候选不会被沿用。
- 交易日历暂时未发布当天日期时：额外检查当天实际日线行情；只有实际拿到有效行情才认定为交易日，避免节后首个交易日因日历发布延迟被错误跳过。
- 非交易日：自动跳过市场数据更新，不生成虚假的交易日候选结果。
- 同时保留手动触发入口，便于对指定日期任务进行云端重跑。

所有正式运行和验证均在 GitHub Actions 云端完成。

## 外部公开策略评估

新增独立目录 `research/external_strategy_tests/`，用于统一测试已搜索到的公开策略。该模块复用公开仓库现有历史行情和日线特征，在统一的T日收盘信号、T+1开盘入场、T+2起退出、交易成本与持仓约束下比较累计收益、年化复利、最大回撤、夏普及严格净收益目标胜率。

当前模块包含三组可运行研究：公开短线选股规则近似复现、趋势回调缩量代理规则、20日动量基线。无法用现有日线公平还原的策略会登记具体数据缺口与复现限制，不混入可运行策略排名。

专用工作流：`.github/workflows/12-external-strategy-tests.yml`。代码提交后自动执行模块质量检查；首次全区间对照由可追溯的标记提交触发一次，后续完整历史评估仍可通过 **Actions →「12 外部策略历史评估」→ Run workflow** 手动启动，结果以工件保存。研究模块不修改正式资产（当前不存在正式发布版本）、不接入正式候选池、不自动下单，也不会重复下载已有历史数据。

评估细节见 [外部策略评估模块说明](research/external_strategy_tests/README.md)。

## 短线研究

`scripts/short_term_research.py` 使用历史日线进行 T 收盘信号、T+1 开盘执行、最长 5 日持有的研究，并输出：

- `data/backtest/short_term_latest.json`
- `data/backtest/short_term_sensitivity.json`
- `data/backtest/short_term_exit_diagnostics.json`
- `data/backtest/short_term_release_validation.json`

研究检查未来函数、交易成本、止盈止损假设、候选覆盖、策略来源一致性，并进行开发集、验证集和最终留出集验证。

### 复利研究目标：累计收益 10,000%

研究配置将累计复利收益 `10,000%`（期末本金达到初始本金的 `101` 倍）设为长期研究目标，不是收益保证，也不是降低风控门槛的理由。策略评价必须使用扣除往返成本后的真实可执行组合收益，不能把“曾触及目标价的样本比例”当作复利收益。

- 复利入场概率阈值、止盈和止损参数网格集中在 `config/选股条件研究配置.json` 中，当前研究范围分别覆盖概率阈值 `0.55–0.975`、净止盈目标 `1%–10%`、止损幅度 `1%–5%`。
- 每日排名数量只根据验证集组合复利择优；必须有正累计收益、达到最低交易数并满足最大回撤边界，随后冻结参数，只在最终留出集评估一次。
- 入场概率阈值先按验证集实际复利筛选；只有选出合格的正复利阈值，才会基于该冻结阈值搜索止盈止损，避免把命中率最优阈值误当成复利最优阈值。
- 如果验证集没有符合条件的正复利方案，研究结果明确记录“无合格方案”，不得改用最终留出集反向挑选参数，也不得自动晋级策略。
- 自动化测试同步验证这一门槛：验证集所有候选均亏损或年化复利非正时，入场阈值选择器必须返回“无合格候选”，不能为了输出结果而保留亏损阈值。
- 每份组合报告都将记录累计收益目标、达到 `101` 倍本金所需的年化复利，以及最终留出是否真实达到目标。达到目标之前，不得声称已实现 `10,000%`。

### 路径感知训练实验

`scripts/train_path_aware_gbdt.py` 用于研究 5 个交易日内净收益至少 1%、且在止损前可兑现的短线机会，不修改历史近期训练窗口模型。

- 默认实验：训练特征截止日为 `2022-12-30`，验证期为 `2023-01-03 至 2024-12-31`，最终留出期为 `2025-01-02 至 2026-09-30`。
- 扩展训练实验：训练特征截止日延长至 `2024-12-31`，验证期独立改为 `2025-01-02 至 2025-12-31`，最终留出仅为 `2026-01-05 至 2026-09-30`；固定阈值为上一轮基准 `0.78`。
- 两类实验都会清除标签前瞻窗口跨入下一时间段的样本；验证标签窗口也不得跨入最终留出期。程序校验训练、验证、最终留出按时间顺序排列且不重叠。
- 模型：路径感知 HistGradientBoostingClassifier；训练样本使用可用历史数据，不按类别设置固定数量上限，不做训练样本截断。
- 研究结果输出：`data/backtest/path_aware_gbdt_research_latest.json`。
- 该实验只属于 `research_only`；只有经过独立验证并满足正式门禁，才允许形成新的正式模型版本。
- 日线数据无法判断同一交易日内目标与止损的先后时，研究标签采用“止损优先”的保守规则，避免高估胜率。

### 条件组合挖掘

`scripts/path_rule_mining.py` 用 2015–2022 数据发现可解释的单因子与双条件规则，再使用 2023–2024 选择规则，最后只在 2025–2026-09-30 做一次最终留出检验。

条件组合同时输出：
- 路径胜率
- Wilson 置信下界
- 平均最佳收益
- 5 日收盘收益
- MAE / MFE
- 平均触发目标日 / 止损日

研究结果写入 `data/backtest/path_rule_mining_latest.json`，**只属于 research_only，不会自动改变生产策略**。

### 训练期冻结规则与模型同口径对照

独立研究工作流 11 盘后选股策略统一研究除规则命中率挖掘和模型复利阈值筛选外，还会从训练期统计中冻结一条包含个股分位因子的可解释规则，按与模型相同的每日 Top2、T+1 入场、T+2 起退出、止盈止损、成本和现金约束运行组合回测。2023—2024 验证期只评估该冻结规则；训练和验证标签都严格限制在各自时间区间内，避免五日未来标签越界。模型阈值仍由验证期选出，因此报告会标注模型验证结果的参数选择偏差。2025—2026年9月仅作补充检验，不能称为完全未触碰的独立留出集。相关说明见 docs/盘后选股统一组合研究.md；个股技术指标条件使用当日股票横截面分位值，而非直接套用原始指标数值。研究不自动替换正式模型。

### 零候选时展示最高评分观察名单

当市场风控或个股准入规则导致正式研究候选数为零时，网页仍展示 `data/candidates.json` 中的 `research_observation_candidates` 前五名，并逐只说明未入选原因。观察名单仅从通过基础上市范围、价格、流动性和历史数据门槛的可评分股票中排序，不代表候选，不进入下一交易日模拟执行计划，不得据此下单。

未入选原因根据当前 Private/main 策略门槛生成，包括市场上涨广度或市场中位收益未达标、个股波动与涨跌幅硬风控、模型评分或精度概率低于最低回退线等。市场处于风险规避时，会明确指出市场门槛优先；如个股另有风险违规，也会同时列明。此功能仅提升结果透明度，不改变选股准入、空仓规则、版本校验或正式发布状态。

## 系统边界

生产层只负责短线候选池、研究验证、审计和网页展示。

券商接入、纸上持仓账本和自动下单属于独立后续执行层，不与候选池生产混在一起。

## 研究运行进度与断点恢复

短线研究采用结构化进度日志与可恢复检查点：每个信号日记录开始、完成、进度百分比及关键结果；异常会记录失败事件。研究中断后，检查点通过 GitHub Actions 工件保留，可在手动运行时填写“要恢复的历史运行编号”从最近成功保存的信号日继续，而不是从头重算。检查点同时校验研究区间、成本参数、策略版本和 Private/main 提交号，避免恢复到不一致的代码或参数。

研究阶段检查点只对截至 2026-09-30 的研究历史行情建指纹。截止日之后新增或补齐的日线不会使旧实验失效；只有旧提交、分析依赖、参数、输入结果、Python 依赖及结果摘要全部核验一致，且截止日前行情未发生变化时，才兼容复用旧检查点。对应云端测试覆盖截止日后增量行情、截止日前数据变更和旧检查点兼容校验；测试夹具以 UTF-8 显式编码写入非 ASCII 样本，避免 Python bytes 字面量语法错误。 历史提交文件尺寸指纹通过 Git 支持的 `ls-tree -l` 读取，兼容当前云端 Git 版本。校验不通过则重新执行，正式模型权重始终不受研究恢复流程影响。


### 历史近期训练窗口基准（已归档，仅用于对照）

上一版固定神经网络、0.60 阈值及其旧候选准入逻辑均已归档，只用于历史对照。当前研究链路固定为：**北京时间交易日数据更新 → 增量数据校验 → 校验 Private/main 提交与系统版本完全一致 → 直接调用 2.6.0 私有策略评分与准入 → 生成研究候选与下一交易日模拟计划 → 版本一致性审计 → 网页展示**。旧模型权重不得参与当前候选生成。所有候选、计划和网页必须来自同一 `data/candidates.json` 快照，并匹配 `config/system_version.json`。

### 正式候选链诊断

正式生产策略与严格交易标签的研究结果必须分开判断。历史研究流水线会在固定公开代码基线与固定 Private/main 提交上，额外输出 `data/research/production_candidate_diagnostic.json`，按开发集、验证集和最终留出集统计候选层级、实际管理交易样本、止损/止盈/到期退出以及严格 1% 净收益胜率。该诊断只用于定位性能损失，不修改生产策略、不降低 80% 正式门禁，也不使用未来数据。

## 当前云端模型研究任务

研究工件需包含 `data/backtest/pairwise_rank_compound_latest.json`，用于复核成对排序与分类模型的组合收益。

下一轮增加非线性成对排序挑战模型：沿用分类基准的特征、隐藏层宽度、学习率、正则化、训练区间和严格交易标签，单独比较分类损失与逐日成对排序损失；结果未通过验证前不替换正式模型。

当前系统尚无已发布的正式模型。独立研究工作流为 `.github/workflows/06-model-research.yml`，从 `Aquant-Private/main` 当前策略源开始，执行高精度严格标签研究和路径感知梯度提升研究，并将结果作为 GitHub Actions 工件保存。修改该工作流定义或 `config/system_version.json` 时会自动触发完整云端研究复核；流程先编译并运行私有策略仓库自身的单元测试，再开展研究。普通行情数据提交不会触发完整模型研究。每次策略版本或提交号同步后，应以该工作流的结果验证当前实验；候选池每日更新与历史研究完成度分开判断，研究中的策略可用于当日研究/模拟候选，但未过发布门禁不得标记为正式发布。

研究目标重点从“只提高命中率”扩展到“命中率、平均净收益、收益分布和复利表现”共同评价；研究结果未通过独立验证与正式门禁前，不得写入 `data/models/production_v1.json`。

本次研究流水线的目的，是在保留旧模型供历史审计的同时评估当前 2.6.0 策略。研究任务失败、超时或中断时，不得把旧候选冒充当前结果；当前策略不满足版本或数据门禁时，网页隐藏候选并保持研究状态。

### 研究工作流并发保护

模型研究工作流在 `main` 上采用串行保护：新提交不得取消正在运行的长时研究任务；同一并发组只保留一个等待中的任务。研究仍在 GitHub Actions 云端执行，结果通过工件留存；任何研究实验都不得自动覆盖 `data/models/production_v1.json`。

### 路径感知模型验证集阈值复利筛选

独立工作流 `.github/workflows/09-path-aware-compound-review.yml` 在一次训练后缓存逐日最高的两个可执行候选，并比较复利阈值网格；旧阈值0.78保留为对照。只有验证集完成交易不少于100笔、累计与年化复利为正、最大回撤不超过配置下限，方案才有资格入选。阈值筛选仅使用验证集，最终留出不参与参数选择。

收益和风险统计覆盖完整信号期与最长退出尾窗，包括没有候选、资金闲置的日期，以免少数交易把年化收益抬高。上一轮0.78基准只在验证窗口完成24笔交易，最终留出仅8笔，样本不足以支持生产晋级；这一结果只保留为研究对照。若验证集无合格阈值，不对最终留出反向调参，也不自动替换正式模型。

最终留出期此前已用于路径标签报告和上一轮固定阈值复核，因此新报告仍标记为补充验证，而不是全新未触碰留出集。全部研究均使用T收盘信号、T+1开盘入场、T+2起退出、保守止损优先、既有成本与现金约束，并持续保持 `formal_production_changed=false`，不更改历史研究系统基准或自动下单状态。

所有云端工作流统一通过工作流级 `GIT_CONFIG_COUNT`、`GIT_CONFIG_KEY_0` 与 `GIT_CONFIG_VALUE_0` 将 Git 初始分支设为 `main`，避免 `actions/checkout` 初始化临时仓库时输出默认 `master` 分支提示。新增工作流或使用 `actions/checkout` 的作业必须沿用该配置。云端验收除检查任务结论外，还须检索日志中的 `hint:`、`warning`、`deprecated` 等警告标记；任务运行成功与策略研究达到质量门槛必须分别判断。
