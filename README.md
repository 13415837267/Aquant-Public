# Aquant-Public

A publication/runtime repository for a daily quantitative candidate-pool dashboard focused on China A-shares.

## Runtime

- Daily refresh target: **18:00 Beijing time (UTC+8)**.
- Scheduler: GitHub Actions at `10:00 UTC`.
- Trading-day guard: skips non-trading days when the public calendar endpoint is available.
- Output: a generated top-30 candidate snapshot at `data/candidates.json`.
- Web: Next.js 16 App Router.
- API: `/api/candidates` and `/api/health`.

The public repository is deliberately a release-safe runtime surface. Strategy research remains in `Aquant-Private`.

## Data source

v0.1 uses **AKShare's Eastmoney A-share spot interface**. The interface is documented by AKShare as an all-market/exchange-level A-share quote source and exposes fields used by the first factor model, including price change, turnover, transaction amount, PE/PB and 60-day return.

The provider is isolated in `scripts/update_candidates.py` so a later release can add another provider without changing the dashboard contract.

## Strategy model

The current release uses a transparent rank-based cross-sectional score:

| Factor | Weight | Runtime signal |
|---|---:|---|
| Momentum | 30% | 60-day return strength |
| Liquidity | 20% | log transaction amount |
| Value | 20% | inverse positive PB/PE proxy |
| Risk | 15% | lower intraday range proxy scores higher |
| Activity | 15% | volume ratio × turnover |

Universe hygiene excludes names matching `ST|退`, stocks priced at or below 2 CNY, and rows with transaction amount below 20 million CNY.

This is a research signal, not an order-execution system or a promise of future returns.

## Open-source design influences

The architecture takes ideas from established open-source projects without copying their implementation:

- **Microsoft Qlib** — modular data/research/model workflow separation.
- **FinRL / FinRL-X** — decoupled data, strategy, risk and runtime layers.
- **VectorBT** — vectorized/cross-sectional experimentation.
- **Backtrader** — explicit strategy lifecycle and maintainable backtesting boundaries.
- **AKShare** — public-source market-data collection and normalization.

## Repository maintenance rule

Every code update must be recorded in `CHANGELOG.md` in the same pull request. The quality workflow checks this automatically for code/workflow changes.

Data-only refreshes are generated by the scheduled workflow and are recorded in Git history with the `data:` commit prefix.

Suggested commit style:

```
strategy: add low-volatility factor
ui: add candidate detail panel
data: refresh daily candidate pool
ops: harden scheduled pipeline
docs: update architecture
```

## GitHub Pages

The public dashboard is configured for GitHub Pages with Next.js static export.

Expected site URL:

`https://13415837267.github.io/Aquant-Public/`

Every push to `main` triggers the Pages deployment workflow. The daily data workflow updates `data/candidates.json` and the immutable history snapshot; that commit then triggers a fresh static-site deployment.

## Deployment

The repository is Vercel-friendly and contains a Next.js production build. Connect this public GitHub repository to Vercel to enable automatic deployments after pushes to `main`. A Vercel Cron endpoint is not required for the Python data job; GitHub Actions is the source of truth for the 18:00 data refresh.
