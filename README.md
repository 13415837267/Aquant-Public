## 数据与策略

`Aquant-Private/main` 是唯一策略源；当前第一版系统基准为 **近期训练窗口研究版**，训练窗口为 2019-01-02 至 2026-09-30，候选概率阈值为 0.60，最多保留模型概率最高的 2 个候选。

`Aquant-Public` 负责历史数据、候选生产、下一交易日计划、研究审计、质量检查、GitHub Actions 和 GitHub Pages。

所有项目计算统一通过 GitHub Actions 云端运行；本地设备不是项目运行环境。仓库执行分支只保留 `main`。

生产运行直接 checkout `Aquant-Private/main` 做来源审计；当前候选生成使用已物化并锁定的第一版模型权重，模型版本、模型代码提交号、训练窗口和候选参数均必须与 `config/production_release_v1.json` 一致。日常生产不重新训练模型。

## 工作流架构

当前主动工作流已整理为单一生产链与两个独立研究入口：

- `01 Python质量检查`：代码质量、语法和测试。
 该检查只在 Python 代码、测试、依赖或工作流文件变更时触发；纯历史数据检查点不会触发新的代码质量任务，避免长流程的数据提交互相取消。
- `02 数据维护`：每天北京时间18:00判断A股交易日并维护增量历史数据。
- `03 候选池生产`：仅在 `02 数据维护` 成功后，使用固定 `production_v1.json` 动态识别最近已完成交易日，生成候选池和下一交易日计划。
  02 成功后由 `workflow_run` 直接进入候选生产，不再根据当前自然日的“是否交易日”重复拦截；跨过午夜时仍以02刚落库的最近完成交易日生成候选。候选结果提交时若其他质量检查等任务同时更新 `main`，会自动回基重试，避免候选已算出却因并发推送失败而丢失。
- `04 历史研究流水线`：正式研究、三段式时间切分、研究门禁和检查点。
- `05 网页自动部署`：候选生产成功完成后自动触发，也保留手动部署入口；网页始终读取当前 `main` 的候选快照，不维护独立候选数据。
- `06 模型研究`：独立实验入口，当前运行高精度严格标签与路径感知 GBDT。
- `07 历史候选回放`：手动指定历史信号日，复现固定模型候选。

此前会因 `data/**` 更新而重复启动的两个独立训练工作流已移除；对应研究 Python 脚本继续保留，但不再自动触发。

## 自动更新

北京时间每天 **18:00** 自动触发市场数据更新检查。

自动任务先读取中国 A 股交易日历：
若因错过北京时间18:00或工作流中断导致最近完成交易日尚未落库，可手动运行 `02 数据维护` 并启用“非交易日补齐最近一个已完成交易日的数据”输入项；该恢复模式只补齐缺失的最近完成交易日，不改变正式模型和候选规则。
- 数据维护采用“最新完整日期 + 1 → 最近完成交易日”的增量区间，只处理缺失交易日，不重新下载或重建已有历史数据。
- 增量起点仅依据历史文件存在性和基本日线字段确定；估值字段完整性由独立质量检查负责，避免字段版本差异导致重复重建旧日期。
- 历史文件为 `.csv.gz` 压缩格式，增量判断按完整文件名去除 `.csv.gz` 后解析日期，避免误把现有历史识别为不存在而回退到历史起点。
- 日线质量检查只验证仓库中最近已经落库且结构完整的交易日；北京时间18:00前不把当天尚未收盘的行情当作质量检查对象，避免开盘前误检当天数据。


- 实际交易日：只增量更新最新行情与历史数据，完成数据校验后读取当前固定模型进行推理，再生成候选池、下一交易日计划、历史归档，并触发网页自动构建部署。
- 交易日历暂时未发布当天日期时：额外检查当天实际日线行情；只有实际拿到有效行情才认定为交易日，避免节后首个交易日因日历发布延迟被错误跳过。
- 非交易日：自动跳过市场数据更新，不生成虚假的交易日候选结果。
- 同时保留手动触发入口，便于对指定日期任务进行云端重跑。

所有正式运行和验证均在 GitHub Actions 云端完成。

## 短线研究

`scripts/short_term_research.py` 使用历史日线进行 T 收盘信号、T+1 开盘执行、最长 5 日持有的研究，并输出：

- `data/backtest/short_term_latest.json`
- `data/backtest/short_term_sensitivity.json`
- `data/backtest/short_term_exit_diagnostics.json`
- `data/backtest/short_term_release_validation.json`

研究检查未来函数、交易成本、止盈止损假设、候选覆盖、策略来源一致性，并进行开发集、验证集和最终留出集验证。

### 路径感知训练实验

`scripts/train_path_aware_gbdt.py` 当前用于研究严格 1% 净收益机会，不修改第一版正式模型：

`T+1 开盘 → 5 个交易日内净收益 ≥3% 的目标先触发，且此前未触发 T+2 起的 -3% 止损`

- 训练区间：2015-01-05 起至 2024-12-31
- 验证区间：2025-01-02 至 2025-12-31
- 最终留出：2026-01-05 至 2026-09-30
- 模型：路径感知 HistGradientBoostingClassifier
- 训练样本：2015–2022 训练区间内全部有效样本，不按类别设置 250,000 上限，不做训练样本截断
- 候选诊断阈值：0.50–0.99
- 研究结果输出：`data/backtest/path_aware_gbdt_research_latest.json`
- 该实验只属于 `research_only`；只有经过独立验证并满足正式门禁，才允许形成新的正式模型版本。
- 日线数据无法判断同一交易日内目标与止损的先后时，研究标签采用“止损优先”的保守规则，避免高估胜率。

### 条件组合挖掘

`scripts/path_rule_mining.py` 用 2015–2022 数据发现可解释的单因子与双条件规则，再使用 2023–2024 选择规则，最后只在 2025–2026-09-30 做一次最终留出检验。

条件组合同时输出：
- 路径胜率
- Wilson 置信下界
- 平均最佳收益
- 5 日收盘收益
- MAE / MFE
- 平均触发目标日 / 止损日

研究结果写入 `data/backtest/path_rule_mining_latest.json`，**只属于 research_only，不会自动改变生产策略**。

## 研究运行进度与断点恢复

短线研究采用结构化进度日志与可恢复检查点：每个信号日记录开始、完成、进度百分比及关键结果；异常会记录失败事件。研究中断后，检查点通过 GitHub Actions 工件保留，可在手动运行时填写“要恢复的历史运行编号”从最近成功保存的信号日继续，而不是从头重算。检查点同时校验研究区间、成本参数、策略版本和 Private/main 提交号，避免恢复到不一致的代码或参数。


### 第一版系统基准（当前有效）

旧 2.5.0 候选准入、0.89/0.88 回退和 Top-1 rescue 规则已从当前生产链路移除；它们只保留在历史审计文件中，不参与当前候选生成。当前链路固定为：**北京时间交易日数据更新 → 增量数据校验 → 读取第一版固定模型权重 → 仅用当日及此前可见数据生成特征 → 概率阈值 0.60 → 模型概率最高的最多 2 个候选 → 下一交易日计划 → GitHub Pages 自动部署**。日常候选生产不重新训练。所有候选、计划和网页必须来自同一 `data/candidates.json` 快照。

### 正式候选链诊断

正式生产策略与严格交易标签的研究结果必须分开判断。历史研究流水线会在固定公开代码基线与固定 Private/main 提交上，额外输出 `data/research/production_candidate_diagnostic.json`，按开发集、验证集和最终留出集统计候选层级、实际管理交易样本、止损/止盈/到期退出以及严格 1% 净收益胜率。该诊断只用于定位性能损失，不修改生产策略、不降低 80% 正式门禁，也不使用未来数据。

## 当前云端模型研究任务

当前正式第一版生产模型保持不变，不因研究任务自动替换。独立研究工作流为 `.github/workflows/06-model-research.yml`，每次研究从 `Aquant-Private/main` 当前策略源开始，执行高精度严格标签研究和路径感知梯度提升研究，并将结果作为 GitHub Actions 工件保存。

研究目标重点从“只提高命中率”扩展到“命中率、平均净收益、收益分布和复利表现”共同评价；研究结果未通过独立验证与正式门禁前，不得写入 `data/models/production_v1.json`。

本次恢复研究流水线的目的，是在不破坏第一版正式基准的前提下继续寻找更高期望收益的策略。研究任务失败、超时或中断时，不影响当前正式候选池和固定模型。
