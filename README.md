# Aquant-Public

个人量化交易系统的**第一版正式运行仓库**：负责数据维护、训练基准候选生成、下一交易日计划、历史归档和网页展示。

当前生产目标：**1–5 个交易日短线**。

核心硬目标：**单笔净利润达到 1% 才计为胜，历史留出验证目标胜率 >80%**。第一版系统工程链路已正式启用；策略质量门槛仍固定为 80%，当前训练基准最终留出胜率为 62.32%，因此第一版只提供研究/模拟信号，不自动下单。

交易时序：`T 收盘信号 → T+1 开盘进入 → T+2 起最早退出 → 最长 5 个完整交易日`

## 数据与策略

`Aquant-Private/main` 是唯一策略源；当前第一版系统基准为 **近期训练窗口研究版**，训练窗口为 2019-01-02 至 2022-12-30，候选概率阈值为 0.60，最多保留模型概率最高的 2 个候选。

`Aquant-Public` 负责历史数据、候选生产、下一交易日计划、研究审计、质量检查、GitHub Actions 和 GitHub Pages。

所有项目计算统一通过 GitHub Actions 云端运行；本地设备不是项目运行环境。仓库执行分支只保留 `main`。

生产运行直接 checkout `Aquant-Private/main` 做来源审计；当前候选生成使用已验证的近期训练窗口模型，并在候选快照、计划和网页中锁定同一训练基准版本。

## 自动更新

北京时间每天 **18:00** 自动触发市场数据更新检查。

自动任务先读取中国 A 股交易日历：
- 实际交易日：更新行情数据与增量历史，完成数据校验后自动生成候选池、下一交易日计划、历史归档，并触发网页自动构建部署。
- 非交易日：自动跳过市场数据更新，不生成虚假的交易日候选结果。
- 同时保留手动触发入口，便于对指定日期任务进行云端重跑。

所有正式运行和验证均在 GitHub Actions 云端完成。

## 短线研究

`scripts/short_term_research.py` 使用历史日线进行 T 收盘信号、T+1 开盘执行、最长 5 日持有的研究，并输出：

- `data/backtest/short_term_latest.json`
- `data/backtest/short_term_sensitivity.json`
- `data/backtest/short_term_exit_diagnostics.json`
- `data/backtest/short_term_release_validation.json`

研究检查未来函数、交易成本、止盈止损假设、候选覆盖、策略来源一致性，并进行开发集、验证集和最终留出集验证。

### 路径感知验证

`scripts/train_path_aware_model.py` 把“5 日内曾达到 +1%”升级为可交易路径定义：

`T+1 开盘 → 净利润 ≥1% 的目标先于 -3% 止损触发`

同一日同时触及目标和止损时采用止损优先的保守假设；T+1 开盘处于涨停买不到的样本不计为可执行交易。

最新路径感知研究表明：验证集路径胜率约 **65.4%**，最终留出集约 **66.9%**，因此当前模型**尚未达到正式生产标准**。

### 条件组合挖掘

`scripts/path_rule_mining.py` 用 2015–2022 数据发现可解释的单因子与双条件规则，再使用 2023–2024 选择规则，最后只在 2025–2026-09-30 做一次最终留出检验。

条件组合同时输出：
- 路径胜率
- Wilson 置信下界
- 平均最佳收益
- 5 日收盘收益
- MAE / MFE
- 平均触发目标日 / 止损日

研究结果写入 `data/backtest/path_rule_mining_latest.json`，**只属于 research_only，不会自动改变生产策略**。

https://13415837267.github.io/Aquant-Public/

网页统一采用中国 A 股显示习惯：**红涨、绿跌、平盘中性**。当前网页不连接券商、不自动下单。

## 系统边界

生产层只负责短线候选池、研究验证、审计和网页展示。

券商接入、纸上持仓账本和自动下单属于独立后续执行层，不与候选池生产混在一起。

## 研究运行进度与断点恢复

短线研究采用结构化进度日志与可恢复检查点：每个信号日记录开始、完成、进度百分比及关键结果；异常会记录失败事件。研究中断后，检查点通过 GitHub Actions 工件保留，可在手动运行时填写“要恢复的历史运行编号”从最近成功保存的信号日继续，而不是从头重算。检查点同时校验研究区间、成本参数、策略版本和 Private/main 提交号，避免恢复到不一致的代码或参数。


### 第一版系统基准（当前有效）

旧 2.5.0 候选准入、0.89/0.88 回退和 Top-1 rescue 规则已从当前生产链路移除；它们只保留在历史审计文件中，不参与当前候选生成。当前链路固定为：**北京时间交易日数据更新 → 增量数据校验 → 近期训练窗口模型推理 → 概率阈值 0.60 → 模型概率最高的最多 2 个候选 → 下一交易日计划 → GitHub Pages 自动部署**。所有候选、计划和网页必须来自同一 `data/candidates.json` 快照。

### 候选覆盖策略

当前候选池采用两级准入：优先保留精度概率 `>=0.89` 的最多 2 个主候选；若主门槛无命中时先尝试满足 `>=0.88` 概率与硬风控的 1 个回退候选；若仍无命中，而市场不是 `risk_off`，则使用历史研究验证过的“每日模型 Top-1”再保留 1 个候选。risk_off 仍严格 0 候选。0.88 阈值和每日 Top-1 均有历史留出研究依据，但都不是执行约束后的生产胜率证明。


### 空池策略边界

正常或中性市场不再因为单一概率阈值过窄而机械空池：准入顺序为 `0.89 主层 → 0.88 回退 → 每日 Top-1 rescue`。只有市场进入 `risk_off`，或全部候选均未通过统一硬风控时才允许 0 候选。每日 Top-1 rescue 只保留 1 个标的，不会扩张仓位上限。


当前候选策略采用 `0.89 主层 → 0.88 回退 → 0.85 Top-1 rescue`，rescue 仍受统一硬风控限制；只有 `risk_off` 或所有标的均低于 0.85/硬风控失败时才允许空池。

### 正式候选链诊断

正式生产策略与严格交易标签的研究结果必须分开判断。历史研究流水线会在固定公开代码基线与固定 Private/main 提交上，额外输出 `data/research/production_candidate_diagnostic.json`，按开发集、验证集和最终留出集统计候选层级、实际管理交易样本、止损/止盈/到期退出以及严格 1% 净收益胜率。该诊断只用于定位性能损失，不修改生产策略、不降低 80% 正式门禁，也不使用未来数据。
