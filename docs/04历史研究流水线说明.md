# 04 历史研究流水线说明

本流水线只在 GitHub Actions 云端执行训练、历史研究和验证，不使用本地设备参与运行。

## 当前研究纪律

- 公开仓库与个人策略仓库均只使用 `main` 一个分支。
- 训练与验证统一遵守北京时间、T+1 开盘入场、T+2 起允许退出、最多持有 5 个交易日。
- 严格标签：先触发 -3% 止损即失败；只有在止损前达到净收益至少 1% 才算成功。
- 04 长任务按研究日期持久化，每 5 个研究日形成检查点，并持续写入进度日志。
- 研究门禁不得通过降低阈值或修改最终留出集来制造通过。
- 梯度提升模型属于独立研究实验；只有验证集和最终留出集均达到正式门禁，且完成审计后，才允许进入后续策略候选。

## 本次新增实验

`scripts/train_path_aware_gbdt.py` 使用历史训练区间建立路径感知梯度提升分类模型，在验证集选择阈值，再只评估一次最终留出集。实验结果以工作流产物保存，不自动修改正式策略。

## 下一轮单变量实验

在不改变严格标签、验证集、最终留出集、模型结构和正式门禁的前提下，增加“近期训练窗口”实验：仅把训练起点从 2015-01-05 改为 2019-01-02，其余参数保持不变。该实验用于检验市场状态漂移下缩短历史训练窗口是否改善 2023-2026 的泛化能力；结果仅作为研究依据，不自动进入生产。


## 60%以上研究试运行版

近期训练窗口实验最终留出在概率阈值 0.60 下取得 604,453 个样本、62.32% 胜率，威尔逊下界 62.20%，样本覆盖率 51.68%；验证集为 59.15%。该结果仅用于网页观察和模拟研究，正式生产门槛仍为 80%，不会因为试运行而解除生产门禁。

## 训练基准切换与候选池重建

本次基准切换以近期训练窗口模型作为当前候选池唯一研究基准：训练区间为 2019-01-02 至 2022-12-30，验证区间为 2023-01-03 至 2024-12-31，最终留出区间为 2025-01-02 至 2026-09-30。候选生成固定采用概率阈值 0.60，并从通过阈值的标的中取模型概率最高的 2 个；不再使用旧 2.5.0 的候选准入、覆盖回退或每日首选救援规则。

候选生成在 GitHub Actions 云端重新训练同一近期窗口模型后，对最新已完成交易日逐标的推理。候选、下一交易日计划和网页必须逐项继承同一快照；正式生产门禁仍保持 80%，当前版本只能用于研究/模拟。旧候选仅进入 candidates_history 作为历史审计，不参与当前候选生成。


## 百分之三路径模型实验：市场状态独立路由

本轮研究目标是在 T+1 开盘入场、T+2 起允许止损、最长观察 5 个交易日的约束下，把“净收益至少 3% 的机会”作为正样本；T+1 触达目标只计为成功机会，不允许 T+1 卖出；若 T+2 起先触发 -3% 止损，则该样本失败。研究使用 2015-01 至 2026-09 历史数据，保持验证集与最终留出集独立，正式生产模型不受影响。

本轮采用市场广度三状态独立路由：风险规避（广度低于 35%）、中性（35%至65%）、风险偏好（不低于 65%）。三个状态分别训练独立逻辑回归模型，推理时按信号日市场状态自动路由到对应模型。此前的市场状态交互特征实验未保留，本轮只比较路由模型相对上一基准的验证集、最终留出集、阈值胜率、每日 Top2/Top5/Top10、平均最高收益和五日收盘收益。

本轮首次云端运行因结果序列化仍残留单模型字段引用而失败，训练阶段已完成但写结果阶段异常；随后修复为按三个状态分别保存模型参数。第二次运行又发现市场广度原始数据为百分数而路由阈值使用0至1比例，导致状态路由失真；现已统一单位后重新训练。修复前结果不纳入实验比较，研究结果仍不得写入正式生产模型。


## 百分之三路径模型实验结果：市场状态独立路由

广度单位修复后的云端训练运行已成功完成。验证集每日 Top2 路径胜率为 69.14%，最终留出集每日 Top2 为 64.20%；对应平均最高收益分别为 11.38% 和 9.87%。但最终留出集每日 Top2 五日收盘收益为 -3.44%，且验证集与最终留出集均未达到 80% 正式门禁，因此本实验仅保留为研究基准，不进入正式生产。

本轮结果确认市场状态独立路由比此前未正确路由的实验结果更有信息量；但仍存在“触达 +3% 机会与最终持有收益不一致”的问题。下一轮保持数据区间、标签、路由结构、学习率、L2 和训练流程不变，仅将正样本权重由 2.0 调整为 3.0，检验提高错失机会惩罚后的排序精度是否改善。


## 少量日期空仓风险过滤实验

在保持百分之三路径标签、三状态独立路由和正样本权重不变的前提下，增加日期级风险过滤：当某交易日全部候选中最高模型概率低于设定下限时，该日不建立新仓。过滤只使用信号日可见的模型概率，不读取未来收益；验证集在空仓比例不超过15%的范围内选择运行点，再对最终留出集进行一次检验。该实验不改变正式生产模型。


## 不兼容历史断点的恢复处理

历史研究断点只有在窗口、交易成本、策略版本、策略提交号、状态结构版本和检查点周期全部一致时才允许续传。旧断点若与当前固定策略提交不一致，流水线会记录不兼容字段并从头重算该研究区间，不再把不兼容错误直接升级为整条工作流失败，也不会复用旧特征状态、旧样本统计或旧候选结果。重算期间每五个研究日仍提交检查点；兼容断点则继续从最近成功位置恢复。该处理只影响研究过程，不修改正式模型或生产候选规则。


## 研究验证代码变更后的云端重跑

历史验证程序、对应测试、研究契约或本工作流发生变更时，04 工作流会在 GitHub Actions 云端自动触发。先由 01 Python 质量检查验证代码和测试；04 仍使用契约中锁定的 Private/main 提交、数据截止日、时间切分和正式门禁。若断点与新契约不兼容，则按记录的规则重算研究区间；只有完全兼容的断点才能续传。



## 研究标签与可执行交易一致性修复（单变量实验）

审计发现，部分训练标签以 T+1 开盘价计算止盈止损，但未统一排除“开盘价达到涨停价、正式策略禁止入场”的样本；正式模拟交易的 `managed_trade` 已排除这些不可执行入场，导致训练标签与回测交易样本定义不一致。

本次修复在共享的可执行入场掩码中统一执行 T+1 开盘价有效性与开盘涨停限制。1% 严格标签、高精度模型、路径感知 GBDT（共享 1% 标签）及 3% 路径模型均复用该规则。不可执行样本从训练与评估样本集中剔除，而不是被当作亏损或盈利，以免模型学习到实际无法成交的信号。

本实验固定原始模型结构、训练窗口、验证窗口、最终留出窗口、交易成本和放行门槛，只修正入场可执行性标签。验收先检查语法与单元测试，再运行云端全市场训练；比较修复前后的有效样本数量、验证集命中率、最终留出命中率、每日 Top-K 实际路径胜率和可执行组合收益。最终留出结果只用于验收，禁止据此反复挑选阈值或改参数。正式模型资产不自动替换。


符号代码匹配使用六位数字正则；本修复的云端测试显式覆盖可执行样本保留和涨停开盘样本剔除，避免因代码格式化错误将全市场样本误剔除。


回归测试还覆盖同一交易日的多证券映射：逐证券核对开盘价与涨停价，确保剔除只作用于对应的不可执行证券，不会因代码映射造成全市场样本误筛。


## 训练与验证切分的前瞻标签清除

另外排查到部分分类/路径模型在切分边界前仍保留了会用到下一阶段行情的训练标签。例如训练日虽属于训练窗口，但它的五日结果标签可能跨入验证期；验证期末的标签也可能跨入最终留出期。这会把后一阶段的结果混入前一阶段，抬高验证可信度。

本次统一增加按交易日索引计算的标签窗口清除：训练标签的最后结果日必须严格早于验证开始日；验证标签的最后结果日必须严格早于最终留出开始日。该规则覆盖 1% 短线模型、高精度模型及 3% 市场状态路由/可执行路径模型。路径感知 GBDT 原有的边界清除保留不变。只修复样本切分，不改变阈值、特征、模型结构、成本或正式门槛；所有结果在云端重算后再与修复前的同口径基准对比。


## 固定规则的成对排序实验（非阈值调参）

本轮新增一个结构性挑战模型：训练目标由逐只股票的二分类损失改为同一信号日内“严格标签成功样本的排序分高于失败样本”的成对逻辑损失。每日最多抽取固定数量的正负样本组成训练对，随机种子固定；特征、1%净收益标签、训练/验证/最终留出窗口、交易成本与正式放行门槛均不调整。

该实验不搜索概率阈值，只比较每日 Top1/Top2/Top3/Top5/Top10 的严格标签命中率，并在每日固定 Top2、T+1 开盘入场、T+2 起止盈止损、最多持有五个交易日、相同成本和现金约束下，与同批训练的两层分类模型做实际组合回测对照。验证组合结束日期会提前清除五日持有窗口，确保交易不会跨入最终留出期间。最终留出集只用于一次预先定义的基准/挑战模型对照，不根据其结果再改参数；成对排序模型不自动进入生产。

成对排序复利对照产物以 UTF-8 格式输出为标准 JSON 文件，便于后续使用同一指标口径进行审计、比对与复核。


## 旧版长任务与修复版任务隔离

本轮标签可执行性及时间切分规则修复后，早先提交启动的长任务仍可能占据原有并发组。为避免旧版长任务阻塞新验证，历史研究工作流使用独立并发组版本标识 `v3`。研究检查点路径按研究实现与配置文件指纹分目录保存；指纹发生变化时，旧检查点不会被复用。新版验证结果写入独立文件 `data/backtest/short_term_release_validation_v2.json`，与旧版运行产物隔离，避免仍在运行的旧任务覆盖新版结果。旧版运行仅作为历史审计，不采用其研究产物；该隔离不改变正式生产模型、候选池或下单规则。

历史验证输出路径会先解析为仓库内绝对路径，再提交检查点和审计结果，确保每次检查点提交记录的路径可相对仓库根目录定位。


## 复利模拟的未来完整路径选择偏差修复

审计复利模拟发现，旧版先以整个未来五日路径是否完整筛候选，再按模型分数取每日前十名。这将未来停牌、缺失行情或五日路径完整性带入选股环节，造成未来信息泄漏，并可能人为移除无法获利或无法平仓的持仓。

新版把选股和结果标签拆开：选股只使用信号日特征及 T+1 开盘实际可成交信息（开盘有效、涨停价有效且未停牌）；未来五日路径完整性仅作为统计诊断和训练标签完整性检查，不再参与候选准入。候选入选后若后续出现停牌/缺失日线，会保留持仓并沿用最后可见价格估值，不制造虚构止盈或止损成交；到回测结束仍未平仓的仓位单独输出数量和证券代码。缺失涨停价按生产模拟规则拒绝入场。

验收新增固定证券排序、涨停入场和未来日线缺口回归测试。此修改可能降低原回测命中率和复利成绩；修正后的结果才可用于判断策略是否真正达到目标。正式生产模型保持不变。


## 研究任务启动前质量门禁

06 模型研究现在在安装依赖后先执行完整 Python 语法检查与自动化测试。任一测试失败时，后续全市场研究步骤不会启动，避免在标签、撮合或前瞻边界规则不一致时浪费长时间云端计算。标签样本测试夹具必须显式提供有效涨停价和未停牌状态，与生产入场契约一致。


## 2026-10-11 成对排序检查点与定向复核修复

审计发现，06 工作流的共享缓存恢复路径曾包含 `pairwise_rank_compound_latest.json`，但对应的保存路径清单没有该文件。GitHub Actions 缓存版本会根据缓存路径清单生成；恢复与保存路径不同，已保存的共享检查点就无法按原版本恢复。现已将共享缓存恢复清单恢复为与原保存清单一致，并把成对排序结果和阶段检查点放入独立缓存命名空间，兼容既有历史缓存。

成对排序对照现由 `scripts/research_checkpoint_runner.py` 执行，检查点会校验模型输入、依赖代码、研究配置、历史数据指纹及输出摘要；失败阶段不标记为成功，下一轮会重新执行，而不是误用失败产物。06 工作流并发组升级为 `v4`，用于隔离早期仍未结束的旧版长任务，避免旧任务阻塞修复后的验证。

新增 `08 成对排序定向复核` 工作流，可直接复用云端已有的高精度研究缓存，仅运行每日 Top2 可执行复利对照，并上传独立日志与结果，便于迅速定位失败，不必为诊断重复训练全市场模型。该工作流只产出研究证据，不修改正式模型、生产候选规则或放行门槛。

本次修改只修复云端复核、检查点与恢复机制；在定向回测和正式历史门禁都通过前，不将成对排序模型替换到生产。


## 2026-10-11 成对排序命令行导入故障修复

GitHub 云端定向复核已复现入口错误：直接执行 `python scripts/pairwise_rank_compound_backtest.py` 时，解释器先把脚本所在的 `scripts/` 目录放入模块搜索路径，脚本却在初始化仓库路径前导入 `scripts.compound_portfolio_backtest`，因此在正式回测开始前即报 `ModuleNotFoundError: No module named 'scripts'`。

修复方式是在本地项目模块导入前，根据脚本自身位置解析仓库根目录，并将其加入模块搜索路径；不改变模型、特征、标签、交易时序、成本或选股规则。新增回归测试从仓库之外的临时工作目录调用脚本的 `--help`，确认命令行入口能完成导入。修复须通过 GitHub 云端质量检查和定向复核后，才能将成对排序的回测结果用于研究比较。
