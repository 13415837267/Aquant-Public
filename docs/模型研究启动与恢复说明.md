# 模型研究启动与恢复说明

## 目的

模型研究必须在 GitHub Actions 云端执行。不能仅凭运行记录显示“运行中”就认定任务仍有有效进展；需要同时检查步骤状态、更新时间、日志和研究产物。

## 启动规则

- 优先使用模型研究工作流的手动启动入口，或由研究代码/工作流文件的正式提交触发云端运行。
- 若旧运行长时间停留在同一步骤，且无法确认其仍在推进，应先记录旧运行编号、提交号和最后步骤，再启动独立的新研究运行；不得把旧运行的状态冒充新训练进度。
- 为避免旧运行的并发组阻塞恢复任务，恢复启动可使用新的并发组版本。新运行仍须使用 `main` 单分支，并从兼容检查点恢复，不能重复下载全量历史数据。
- 启动后必须核对新运行编号、提交号、事件类型、首个质量门禁结果和当前步骤；只有出现新运行记录且步骤确实推进，才报告“已启动”。

## 研究验收

- 复用仓库内已有历史行情，研究区间以工作流预检为准。
- 严格遵守时间顺序切分、无未来函数、A股 T+1 执行约束。
- 先按验证集选择参数，冻结后只评估最终留出集；不能通过反复调阈值或查看最终留出集来宣称达标。
- 比较每日成对排序与分类模型时，必须保存 `data/backtest/pairwise_rank_compound_latest.json`，并在相同的 T 日信号、T+1 开盘买入、T+2 起卖出、交易成本和资金约束下比较复利收益、回撤及交易质量；最终留出集不得用于选择模型。
- 保存检查点、研究产物和审计记录；代码或工作流修改必须同步更新说明文档并以中文提交信息提交。

## 下一轮实验：同结构非线性成对排序

上一轮线性成对排序模型未通过验收：验证期组合收益 -26.47%、最终留出期 -4.72%，均低于分类基准的 -17.74% 和 -0.63%。因此下一轮不继续做阈值搜索，而是检验线性排序模型是否因缺少非线性交互而欠拟合。

新训练器 `scripts/train_pairwise_mlp_ranker.py` 使用与分类基准相同的特征清单、隐藏层宽度、权重初始化、学习率、正则化、训练区间和严格可执行路径标签。线性排序模型与非线性排序模型沿用同一随机种子、每日正负样本对数量上限和时间切分。唯一预定变化是模型结构与排序损失的组合：新增模型使用与分类基准同结构的两层感知机，按每个信号日的正负样本对训练。

新增测试文件 `tests/test_pairwise_mlp_ranker.py` 覆盖排序更新方向、无正负样本日跳过与特征维度校验，必须通过 GitHub 云端质量检查。

`scripts/pairwise_mlp_compound_backtest.py` 以固定每日Top2规则同时比较分类基准、线性成对排序和非线性成对排序。三者使用相同的 T 日收盘信号、T+1 开盘入场、T+2 起退出、止盈止损、交易成本、现金约束和历史窗口。验证集不参与新模型训练或阈值搜索；最终留出只作一次确认。新模型未通过实际组合收益、回撤与交易质量评估前，不改变正式生产模型。


## 新一轮实验：直接优化实际可执行净收益

前两轮排序模型仍在优化二元“止盈先于止损”标签，但实盘价值由真实成交路径决定：T+1 开盘买入、T+2 起可退出、同日先触及止损时保守判亏、跳空按开盘估算成交，并计入往返成本。固定每日Top1/Top2也会迫使策略买入低把握候选，不能证明模型具有足够的交易优势。

新增 `scripts/train_executable_return_ranker.py`：使用相同历史特征与 2015—2022 训练窗口，但训练标签改为按正式回测退出函数逐笔模拟得到的实际净收益百分比，并用回归损失优化，而不是二元命中分类或成对排序。输出仅是研究模型。

新增 `scripts/executable_return_backtest.py`：在完全相同的 T+1 入场、T+2 起退出、止盈止损、跳空成交、交易成本、现金约束下，比较分类基准、净收益回归强制Top1，以及预测净收益为正才入场的经济空仓策略。零点来自净收益的盈亏平衡含义，不搜索概率阈值网格。先在验证期比较预先定义的两种挑战策略并锁定一项；最终留出集只评估基准和验证期锁定的挑战策略。

验收仍要求严格目标命中率达到 80%、组合复利为正、最大回撤不低于配置底线且完成交易数充足。若验证期或最终留出期任何门槛未通过，结果只作研究诊断，不晋级正式模型。所有训练、质量检查和回测都由 GitHub Actions 云端执行；正式模型与自动下单设置保持不变。
