## 2. 模型生命周期

生产日常不重新训练。

### 新交易日

02 增量更新数据 → 读取固定模型 → 只使用信号日及此前可见数据 → 模型推理 → 生成候选 → 生成下一交易日计划 → 网页部署。

### 历史日期

读取同一固定模型 → 输入数据截断到目标信号日 → 禁止读取未来行情 → 输出历史截面候选。

### 新模型

只有新的研究模型完成验证并正式发布后，才允许重新训练、物化和替换生产模型资产。

## 3. 当前仓库结构

- data/research：研究和历史回放资料
- app：网页

## 5. 当前禁止事项

- 禁止每日重新训练正式模型。
- 禁止未来函数和数据穿越。
- 禁止同日买入后卖出。
- 禁止旧候选脚本绕过正式候选生产链路。
- 禁止旧研究快照覆盖当前生产状态。
- 禁止网页维护独立于 data/candidates.json 的候选列表。
- 禁止在 Private 以外建立第二套策略源。
- 禁止在本地运行训练、生产验证或正式测试。

## 6. 历史残留处理原则

历史研究结果和失败/恢复记录用于审计，可以保留。

已经失效的运行入口、一次性触发文件、旧生产状态和未被当前工作流引用的候选实现应删除或明确标记为历史资料。

删除不影响 Git 历史追溯；历史版本仍可以从提交记录恢复。
